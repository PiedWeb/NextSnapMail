# Search, list density and rendering, 24 October 2026

Pied Web **1.10.39** is installed on Nextcloud **35.0.2**, NextSnapMail
**0.1.16**, SnappyMail **2.38.2**. Implementation commit: `51504eae4`.

## Changes and measured effect

Advanced search has one folder/subtree/account/all-accounts selector. Folder and
subtree retain native search; wider scopes use the existing account-safe server
workspace. Native controls return when the theme is disabled. Cancelling the
popup keeps the committed scope. Subtree matching uses the actual IMAP delimiter
and includes the selected folder, without matching similarly named siblings.

Desktop list width is capped at 480 px. Reduced padding, shorter date headings
and visible row dates give more scanning space while preserving typography,
unread hierarchy, long subjects, phone touch commands and native selection.
The sidebar remains 248 px so folder captions fit. Long content can still grow.

Fictional fixtures at the same 1536 × 788 viewport show normal rows falling from
83 to 60 px and fully visible messages increasing from 7 to 10. At 390 × 844,
the representative fixture increases from 8 to 10; real content varies. The
first global navigation issues one scan instead of two. For 500 fictional rows
in 100 groups, grouping performs 2500 identity reads instead of 26850 and retains
unchanged heading nodes. These are deterministic fixture measurements, not a
claim about production IMAP latency. Identical pending searches share one
request; each search loads server settings only once per account.
