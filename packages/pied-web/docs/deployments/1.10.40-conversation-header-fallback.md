# Conversation header fallback, 26 October 2026

Pied Web **1.10.40** is installed on Nextcloud **35.0.2**, NextSnapMail
**0.1.16**, SnappyMail **2.38.2**.

## Problem and correction

Production IMAP returned successful empty searches for Message-ID, References
and In-Reply-To, including a source Message-ID independently verified with
BODY.PEEK. From/UID searches worked. This establishes an IMAP header-search
failure; it does not identify the mail server's internal indexing cause.

Conversation discovery now verifies the source UID with native header-only
FETCH and probes its Message-ID. An empty/rejected probe switches to UID
snapshots and batches of at most 50 BODY.PEEK header fetches, using one IMAP
connection. Exact-ID graph matching joins chains across pages and folders;
subject/sender similarity never creates a conversation. Source FETCH must
remain UID-scoped: native unfiltered MessageList clears oSequenceSet.

The fallback retains account/folder boundaries, exclusions, the 160-operation
budget, 12-second checks between commands and 200 returned messages. Incomplete
Inbox results remain visible with Retry, including an original-only result.
The current DraftsFolder/JunkFolder keys and native special-use roles exclude
drafts, junk and trash except an explicitly opened origin. An unset Sent setting
resolves through its native special-use role; explicit disabled Sent remains
disabled. Complete Inbox scans retain cheap etag freshness checks.
