# Deployment: shared Mail design system, 2026-10-06

Pied Web **1.10.24** applies the Mail component contract to native settings and
popups: one-pixel boundaries and focus, stronger focus colour, shared typography,
radii, control sizes, surface elevation, semantic colours and recurring icons.
Sender metadata retains its lighter grey hierarchy relative to the subject.
Native controls, models and command handlers remain in place. A post-binding
adapter associates labels, names actions, adds keyboard activation/reordering
and announces save feedback. Received messages and editor contents are excluded.

Compatibility: Nextcloud **34.0.4**, NextSnapMail **0.1.15**, SnappyMail **2.38.2**.
Source commits: `4091b3398` (shared components), `d24a6b19c` (native principal
account span and final cache version). Release/tag: `piedweb-mail-v1.10.24`.
See [component contract](../DESIGN_SYSTEM.md) and the dated parent workspace audit
`docs/audit-design-system-mail-2026-10-06.md`.

## Verification

The monorepo suite, release fingerprints and reproducible theme build passed.
**27 browser scripts / 568 assertions** passed, including **144** native-component
assertions. The native fixture uses the actual templates, exported Knockout
binding accessors, fictional accounts and mocked commands. It covers one-pixel
rest/focus, strong focus contrast, labels, late mounting, explicit deletion
confirmation, keyboard activation and account sorting through the native
persistence callback. The principal account's three-column span is reproduced
at 320px in both themes. No real send, save, delete or crypto/Sieve operation was
used for testing.

A static sweep rendered **48 templates / 192 combinations** at 1440/390px in
light/dark. The main bound list/reader/composer sweep covered **24 combinations**
at 1440/900/390/320px in both themes: no measured UI text below 4.5:1 and no page
overflow. Received/editor content is excluded. The static sweep intentionally
shows conditional branches together and does not certify their server behavior.
Spinner strokes and transparent layout reservations are not component borders.

Authenticated read-only inspection covered the six available settings routes at
1440/390/320px, plus mailbox, FolderCreate and AdvancedSearch. All visible fields
in the 23 samples had associated names. Active settings/dialog panels fit their
available widths; the Accounts panel at 320px has scrollWidth = clientWidth =
278px. Mobile search scope is readable on a separate full row, its select 274px
wide at a 390px viewport. Native dialogs have no extra border/filter, one shared
elevation and a 44px close target. The raw scan also includes the mailbox behind
modal dialogs; its internal scrollWidth can exceed its clientWidth without page
or active-dialog overflow.

Fresh pages on **nc.robin-d.fr** and **cloud.piedweb.com** loaded the final plugin
and theme markers after maintenance cleanup. Actual mobile focus is 1px, with
stronger colour and no second outline; narrow fields use 16px. Other origins,
physical phone pointers and screen-reader sessions were not certified. Rare
crypto/Sieve branches have static coverage only.

## Installation and web activation

Preflight matched the prior 1.10.22 product **63/63** hashes; the root audit was
**94/94**. Only four runtime paths changed during this task:

- `plugin/pied-web-ux/index.php`
- `plugin/pied-web-ux/native-components.js` (new)
- `plugin/pied-web-ux/ux.css`
- `theme/PiedWeb/snappymail/style.css`

Assets were installed before PHP, with external backups and post-install
fingerprint checks. The temporary 1.10.23 installation exposed the account-table
column span issue at 320px. Its stylesheet correction matched on disk but the web
still served the former CSS: SnappyMail ServiceCss keys its cache by plugin hash,
theme and engine version, not the theme fingerprint. Final 1.10.24 rotates that
key. No Nextcloud or embedded-engine payload was replaced.

Final native CLI compilation: version **1.10.24**, plugin hash
`44a0a5009a7adcab0e322e79b43ca011`, CSS **338799 bytes**, JS **681777 bytes**,
required markers present. CLI compilation alone did not establish web activation.
Authenticated requests on both origins initially executed 1.10.23; targeted
OPcache invalidation then confirmed **1.10.24** in new requests. The fixed-path
maintenance helper was removed after both requests completed, with the original
private configuration bytes restored and no concurrent merge required.

Final root read-only audit: **95/95** fingerprints conformant; service, Calendar,
attachment cache, CSP and .htaccess checks remain conformant. Root evidence:
`evidence/live-2026-10-06-before-design-system.json`,
`evidence/live-2026-10-06-after-design-system.json`, and
`evidence/mail-design-system-homogenisation-2026-10-06/`. These contain only
versions, public fingerprints and sanitized component measurements. The shared
development checkout and unrelated local changes were left untouched.
