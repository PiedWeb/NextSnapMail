# Deployment: complete Mail workspace 1.10.2

Pied Web **1.10.2** and NextSnapMail **0.1.14** were installed on the n0c
production instance on 2026-09-20 from the canonical `PiedWeb/NextSnapMail`
monorepo. The release turns the account and global Feeds into complete,
keyboard-accessible workspaces with scoped server search, durable view state,
multi-page selection, reversible Trash, reminders, compact density and stable
conversation context. Reusable responses were explicitly excluded.

- `tools/test.sh` passed completely: core Node tests, reproducible theme,

- the mailbox-operation suite passed **54** assertions, including immutable

- the fictional browser suite passed **39 of 39** scripts after the final

## Web runtime and read-only browser checks

LiteSpeed initially continued executing Pied Web 1.9.3, then 1.10.1 after the
last file update. The authenticated fixed-path runtime helper invalidated all
**17 of 17** reviewed PHP paths on each pass. Separate requests reported 1.10.1
and finally **1.10.2**. Each cleanup restored `application.ini` byte-for-byte,
removed the temporary plugin and detected no concurrent configuration change.

With no composer or dialog open, the production Mail page was reloaded. The
loaded bundle contained thread expansion, native UIDVALIDITY propagation and
the shared desktop action group. The theme, account-menu global entry, active
scope, page checkbox and native UIDVALIDITY store were present. No message was
opened, sent, moved, deleted, flagged or marked read.

The final live audit matched **94 of 94** tracked files. Nextcloud reported
maintenance off and no pending upgrade. Calendar remained patched; WebDAV
no-abort, scanner short-circuit, one preload HSTS header, 30-day Mail cache and
the multi-domain image CSP all remained conforming.

## Performance record

- production server baseline: five read-only global Feed loads, median 837 ms
  for 83 rows;
- final production server: two five-load read-only series, medians 863 ms and
  847 ms for 84 rows, with no failed account. The server endpoint was unchanged
  by the final DOM iteration and the extra row makes the per-row median
  effectively equal to baseline;
- the desktop action-group iteration reduced production list DOM from 1,469 to
  **975 nodes** (494 fewer, about **34%**) while keeping one active quick-action
  group for 84 global rows;
- fictional 200-message conversation runs kept one search, zero eager body
  reads and 199 stable keyed cards. Current medians ranged from 87 to 98 ms
  versus 226 to 234 ms for the prior scheduling behavior;
- mocked 40,000-message/two-account search: 113.91 ms initial-index median,
  20.83 ms cached-page median and 52.5 MiB peak memory;
- mutation round trips per folder/batch are now one forced examine for prepare,
  one examine plus the final writable select for Trash, and two examines plus
  the final writable select for Undo.

## Rollback

First confirm that the installed files still match the 0.1.14/1.10.2 manifest.
For a full rollback, restore only the files captured under
`mail-workspace-0.1.12-1.9.3-20260920T075718Z`, installing assets before the old
version-bearing files, then run `php -d apc.enable_cli=1 occ upgrade`. For a
plugin-only rollback, use the 1.10.1 backup and install its `index.php` last.
Run the current targeted Web-runtime invalidation procedure, verify the version
through a separate authenticated request, repeat the live audit and reload only
with no composer open. Rollback does not touch mail, account definitions,
credentials or user messages.
