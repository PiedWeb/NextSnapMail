# Deployment 1.7.34, 2026-09-15

Every address in the reader header became a link. A click writes a new message
to it through SnappyMail's own `mailto:` handling, carrying the display name;
Ctrl/Cmd+click, or Ctrl+Enter on the focused address, copies the bare address
instead. The release adds one plugin file, `address-actions.js`, and changes
`ux.css`, the theme stylesheet and the version-bearing `index.php`. No mail
command, binding or native contract is replaced.

## Installation

Files were staged privately, their bytes compared with the 1.7.34 manifest, and
installed assets-first: `themes/PiedWeb/snappymail/style.css`, then `ux.css`,
then the new `address-actions.js`, and the version-bearing `index.php` last, so
the plugin never announced 1.7.34 before the script it loads existed. Installed
hashes equal the manifest (`index.php` `4a851121…`, `address-actions.js`
`8e232a0d…`, `ux.css` `673181ff…`, `style.css` `5ccaa91c…`), 36 plugin files,
mode 644, and the server's own `php -l` accepted the new `index.php`. The
staging directory was removed.

Workers were recycled with `pkill -u robindfr lsphp` followed by a warm-up
request (`status.php` 200); the remaining workers were one to four seconds old.
`~/.lsphp_restart.txt` remains ineffective on this host, as recorded since
1.7.31. The served plugin bundle key changed from
`e90594cd0861bfef4fe98133864dcc91` to `21e817499a3d1c91bd4aaac93e4f86f0`, which
is the only reliable proof of web activation with `opcache.validate_timestamps=0`.
The compiled stylesheet is cached under `/CssCache/<Plugins()->Hash()>/<theme>/`
`<APP_VERSION>/` and that key does not depend on the theme file, so the version
bump is again what makes the changed stylesheet reachable.

## Boundaries

The compose popup itself was deliberately not opened on production: filling a
recipient and closing it can offer to save a draft, and this release is not
worth a draft in a real mailbox. What the popup receives was verified instead —
the recorded `showMessageComposer` parameters above — and the popup path is
exercised end to end in the fixture against the actual mailto parsing of
SnappyMail 2.38.2. The phone behaviour, where a tap writes a new message and a
long press offers the browser's own copy item, was checked at 320 px in the
fixture and not on a physical device.

## Rollback

This release adds a file, so restoring 1.7.33 takes three writes and one
deletion:

- copy `~/nextsnapmail-pied-web-backups/pied-web-ux-1.7.33-20260915T220712Z/`
  `{index.php,ux.css}` over the installed plugin files,
- copy `~/nextsnapmail-pied-web-backups/PiedWeb-theme-1.7.33-20260915T220712Z/`
  `snappymail/style.css` over the installed theme stylesheet,
- delete the installed `address-actions.js`,

then recycle with `pkill -u robindfr lsphp` and a warm-up request and confirm the
bundle key returns to `e90594cd0861bfef4fe98133864dcc91`. Leaving
`address-actions.js` in place with the 1.7.33 `index.php` is harmless — it is
simply never loaded — but the plugin directory would no longer match the 1.7.33
manifest. The 1.7.33 fingerprints are in this repository's git history. This
release writes no data and no configuration.
