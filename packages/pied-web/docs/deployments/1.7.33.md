# Deployment 1.7.33, 2026-09-15

The desktop calendar action no longer hangs off the divider above it. Its hover
and focus surface began exactly where the message metadata rule ends, so
pointing at "Ajouter au calendrier" painted a tinted block glued to that line.
The action row now keeps 6 px below the rule, the spacing the owner chose, and
the existing 12 px before the attachment divider. One declaration changed in the
`min-width:800px` block of `mail-polish.css`; no behavior, binding or native
contract is touched.

production was a clean 1.7.32 with no foreign drift.

Served state before the write, read in an authenticated session: plugin bundle
key `f05092589e13133d939bbb149acaaa6c`, and the inline `app-theme-style` block
carried `margin:0 36px 10px` for `.pw-message-extras`.

## Installation

`themes/PiedWeb/snappymail/style.css` was installed first, the version-bearing
`index.php` last. Installed hashes equal the 1.7.33 manifest (`index.php`
`fae93150…`, `style.css` `b0ef4b90…`), 35 plugin files, and the installed
stylesheet carries `margin:6px 36px 10px` at line 4589.

`~/.lsphp_restart.txt` remains ineffective on this host, as recorded for 1.7.31
and 1.7.32. Workers were recycled with `pkill -u robindfr lsphp` followed by a
warm-up request (`status.php` 200); the remaining workers were one to two
seconds old. The served plugin bundle key changed from
`f05092589e13133d939bbb149acaaa6c` to `e90594cd0861bfef4fe98133864dcc91`, which
is the only reliable proof of web activation with `opcache.validate_timestamps=0`.
The compiled stylesheet is cached under `/CssCache/<Plugins()->Hash()>/<theme>/`
`<APP_VERSION>/` and that key does not depend on the theme file, so the version
bump is what makes a changed stylesheet reachable at all — the same trap as 1.7.31.
