# Deployment: account URL context 1.9.3

Pied Web **1.9.3** and NextSnapMail **0.1.12** were installed on the n0c
production instance on 2026-09-19 from the canonical `PiedWeb/NextSnapMail`
monorepo. Each browser tab now carries its selected mailbox in an opaque
`account` URL parameter. Selecting an account in one tab therefore no longer
changes the account displayed by another tab.

No account address, message or credential is stored in the URL. The identifier
is the existing non-reversible account hash. It is propagated on AppData, JSON,
upload and raw-resource requests; an unknown explicit hash is rejected instead
of falling back to another account. The historical shared cookie remains only
as a compatibility fallback for clients that send no URL context.

The core browser assets now carry a version derived from the deployed source
timestamp. This was added after the first production reload showed that a
previous `app.min.js` could otherwise remain in the browser cache even though
the server files and PHP runtime were current.

- each URL matched the account visibly active in that tab;
- reloading the first tab preserved its account;

- contextual data requests were observed and no loading error appeared.
