# Deployment 1.7.8, 2026-09-14

Newly sent replies now get a read copy in the replied-to folder as well as the
normal Sent copy. SnappyMail 2.38.2 threads only within the current folder, so
the extra copy can join the conversation. This release also includes the 1.7.7
Conversations-button styling, which had been committed but not deployed. No
historical sent messages were copied, and no real mail was sent for validation.

The live instance was Nextcloud 34.0.4.1, NextSnapMail 0.1.11 and embedded
SnappyMail 2.38.2. All 34 installed 1.7.6 payload hashes matched the prior
manifest before installation. The deployment changed only
`plugin/pied-web-ux/index.php`, `theme/PiedWeb/snappymail/style.css` and the new
`plugin/pied-web-ux/ConversationReply.php`. The original two files are backed up
outside the web root at
`~/nextsnapmail-backups/pied-web-ux-v1.7.8-20260914T073745Z/`;
the staged payload and release manifest are at
`~/nextsnapmail-staging/pied-web-ux-1.7.8-20260914T073745Z/`.
The theme and new PHP class were installed before the version-bearing index.

Local validation passed: 35 payload hashes, a reproducible theme build, JS/PHP
syntax, five installation tests, eight fictional send-hook transport checks and
19 unread-draft regressions. The live PHP CLI compiled the plugin as 1.7.8
with hash `d4f71bb865ca30540ad93ac7e3055ac8`. LiteSpeed initially served
the stale 1.7.6 index. The guarded authenticated maintenance hook invalidated
that fixed path; a new Web request reported 1.7.8. The temporary plugin was
removed and its configuration restored byte-for-byte. An authenticated browser
reload showed Mail, the Pied Web theme and the Conversations control, with its
pressed styling computed from the deployed stylesheet. The read-only audit
then matched all 52/52 tracked production files, including Calendar and Office.

The send-hook checks use fictional message bytes and mocked IMAP transport.
They establish that the source-folder append receives the prepared stream,
that Reply all follows it, and that the stream remains usable for Sent even
when the extra append fails. They do not prove threading behavior for every
mail server or verify a real send. A failed extra append is logged without
blocking native Sent storage.

## Rollback

On the n0c host, run:

```sh
python3 "$HOME/nextsnapmail-backups/pied-web-ux-v1.7.8-20260914T073745Z/rollback.py"
```

The script checks the current 1.7.8 and saved 1.7.6 fingerprints before
restoring the two prior files and removing the added class. Follow
`tools/web-runtime-maintenance/README.md` to invalidate the restored index in
the authenticated Web runtime, then reload Mail and check its served version
and theme. The rollback changes no mail, accounts or server configuration.
