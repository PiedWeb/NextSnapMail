# 1.7.2 web runtime activation, 2026-09-12

The owner provided an authenticated Chrome session at `https://nc.robin-d.fr/apps/nextsnapmail/`.
The earlier `cloud.piedweb.com` URL came from server configuration; the live session uses
nc.robin-d.fr. The directly served theme had the same SHA-256 as the SSH deployment.

## Confirmed cause

Fresh authenticated AppData still announced Plugins hash `dc6b0c9609707077dbb790df52330a21`.
The returned bundle matched the old disk JS cache SHA-256
`c310e9159d2cef67202bf1be0d90f56c8cee2a15882c4755367b49d421e9f831` and contained neither
`pwUnreadDrafts` nor `pwMetadataVersion`. The applied theme lacked the 1.7.2 marker,
although the uncached static theme file already matched release.json.

An administrator-only native plugin maintenance hook measured **web PHP version 1.6.4**,
SAPI `litespeed`, `opcache.validate_timestamps=0`, `opcache.revalidate_freq=2`.
The old index.php bytecode registered the old asset list and version/hash, preserving
old compiled CSS/JS. CLI compilation and file equality therefore missed the real failure.

The hook invalidated only index.php, UnreadDrafts.php, FilteredSelection.php and
AttachmentImage.php in pied-web-ux. A subsequent request reported **1.7.2**.
No PHP host setting, global OPcache, mailbox or account/Sieve/calendar setting changed.

## Cleanup and evidence

The temporary plugin was removed and application.ini restored byte-for-byte after a
concurrent-change fingerprint check. Private before/after data remains under
`nextsnapmail-staging/runtime-repair-20260912/`, outside the web root. Reusable guarded
operator scripts are in `tools/web-runtime-maintenance/`; they are not permanent payload.
A standalone routed probe returned 404 and was removed before the native hook was used.

Final web Plugins hash: `9e35e4c379f4c903fc91fda40528b7c4`. Unlike the original CLI hash,
this is measured through the owner's web entry point after removing the temporary plugin.
The differing CLI/web hashes are not by themselves a version comparison, since registered
asset paths participate in hashing.

After reload, the actual Inbox DOM reported `data-pw-metadata-version=1.7.2`, the theme
marker was present, and the native `13/4` control rendered as **13 | 4 non lus**, border 0.
The unread-draft module initialized and its real endpoint returned zero UNSEEN matches;
the ordinary Drafts list contained drafts. Hiding the empty section is the requested behavior.
No draft was marked unread to manufacture a successful example. An existing-mail flagged
search returned no matches, so a live flagged-row example was unavailable; the 1.7.2 amber
styles are loaded and their fictional fixture validation remains documented separately.

Authenticated screenshots were inspected locally and excluded from Git/release archives.
No message was opened, sent, deleted, flagged or marked read/unread during the checks.
Runtime payload and version remain **1.7.2**, unchanged. This is activation of the already
published release, not a new UI implementation. The source commit records operations/tools;
the existing release tag/archive must not be silently replaced.
