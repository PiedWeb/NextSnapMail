# Deployment 1.7.10, 2026-09-14

Opened conversations now show historical replies from the configured Sent
folder in a read-only section below the native thread. The 1.7.8–1.7.9
send-stream hook and its `ConversationReply.php` class were removed. No mail was
sent, copied, moved or deleted during this deployment.

Before installation, Nextcloud 34.0.4.1, NextSnapMail 0.1.11 and embedded
SnappyMail 2.38.2 matched all 35 files in the 1.7.9 release manifest. The
old `index.php`, `ConversationReply.php` and theme stylesheet are backed up
outside the web root at
`~/nextsnapmail-backups/pied-web-ux-v1.7.10-20260914T114017Z/`.
The 1.7.10 assets, the old and new manifests, and guarded install/rollback
scripts are at
`~/nextsnapmail-staging/pied-web-ux-1.7.10-20260914T114017Z/`.
Each changed file was fingerprint-checked before replacement. The new JavaScript
and stylesheet were installed before `index.php`; the old class was retained
until targeted Web OPcache invalidation was requested, then removed under a
fingerprint guard.

Production CLI compilation reported 1.7.10, plugin hash
`79c6963c1b4a33d456ff4dadb53a8f2f`, inclusion of the virtual Sent module,
absence of the copy method and an unchanged configuration fingerprint. The
authenticated Web check initially returned the cached 1.7.9 class. Its targeted
invalidation request completed without an API error, and the temporary
maintenance plugin was removed with the original configuration restored.
The connected Chrome session then stopped accepting automation, while the
standalone fallback had no authenticated session. A fresh Web version and DOM
check could not be completed in this run. The public theme URL served the exact
1.7.10 stylesheet hash. The final read-only server audit found 52/52 expected
payload hashes matching, Nextcloud installed and maintenance mode off; see
`1.7.10.json`.

Eleven fictional browser scenarios and three native header-search checks passed
locally, along with plugin syntax, reproducible theme build and manifest checks.
The unverified point is whether a freshly loaded authenticated Web process and
its plugin bundle now serve 1.7.10 after the invalidation. On next authenticated
browser access, verify the bundle contains the virtual Sent module and that an
opened conversation with a matching historical Sent reply shows the labelled
section. Do not infer this from CLI or installed file hashes alone.

## Rollback

On the n0c host, run:

```sh
python3 "$HOME/nextsnapmail-backups/pied-web-ux-v1.7.10-20260914T114017Z/rollback.py"
```

The script checks current 1.7.10 and saved 1.7.9 hashes, restores the old
class, stylesheet and index, then removes the new JavaScript. Follow
`tools/web-runtime-maintenance/README.md` to invalidate the restored PHP in
the authenticated Web runtime and reload Mail. Rollback does not alter messages
or accounts.
