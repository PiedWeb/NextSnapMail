# Deployment 1.8.10: distinct unread conversation groups, 2026-09-18

This release keeps rows whose visible/root message is unread together before conversations
whose root is read but whose `threadUnseen` metadata reports an older unread member. Fully
read rows still follow newest-first. The change preserves the native read-status indicator
and action instead of making a read root look unread.

## Behavior and performance

The existing in-memory comparator now uses three ranks:

1. unread visible/root messages, oldest-first;
2. read roots with an unread conversation member, oldest-first;
3. fully read rows, newest-first.

This is one integer rank per compared row. It adds no request, IMAP search, payload or DOM
work. The 1.8.9 first-page unread collection, pagination deduplication and per-account
read-transition setting remain unchanged.
